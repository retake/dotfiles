pause/skip/rewind のような **複数の "止まる/進む" 軸** が絡む UX 仕様を新機能として導入する場合、最初に「何が止まり、何が止まらないか」を **軸ごとに 1 つずつ** ユーザーに確認する。

**Why:**
- HO-113 (REQ-49 pause/resume) で 3 回の仕様往復が発生した。
  1. 「進捗バーや進捗サークルも一時停止中に進んでしまう」 → ビジュアルだけ凍結
  2. 「step の時計が止まり、resume 時も pause 開始時の値から続いてほしい」 → step clock も凍結 (two-clock model)
  3. snap-back fix
- 当初の選択肢 (b) は「実時刻継続 / 出発時刻固定 / 復帰時に "あとこれだけ" を再計算」と表現されており、step clock がどうなるかが曖昧だった。
- 軸を分けて確認していれば 1 回目で「step clock も止める」が選択できた。

**How to apply:**
- 選択肢を提示するときは、関連する各軸（wall clock / step clock / 出発時刻 / 進捗バー / 音 / 視覚的フリーズ等）について「止まる」「進む」を 1 つずつ Q として並べる。
- 比較表に "全部止める" / "全部進む" の **極端な選択肢** を必ず含める（中間案だけ並べると意図がぶれる）。
- pause / skip / rewind / undo / freeze 系の新機能で適用する。
