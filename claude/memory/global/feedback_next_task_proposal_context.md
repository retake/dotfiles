次タスクの候補を提示するときは、タスク名だけでなく以下を併記する:

- **どの画面・どのコンポーネントの話か**（例: メイン画面の chapter bar、設定画面の音声選択 など）
- **ユーザーにどんな効果があるか**（体験がどう変わる / 何が解決する）

**Why:** タスク名だけだと「何の改善か」「実施すると何が良くなるか」が判断しづらく、優先順位を決めるコストが上がる。画面と効果がセットなら、ユーザーが即決できる。

**How to apply:**
- /groom や audit 後の推奨タスク表、handoff 候補提示など、次アクションを問う場面すべてで適用
- 表で出すなら列に「画面 / 対象」「ユーザー効果」を含める
- 内部的なリファクタ・ドキュメント整理は「ユーザー効果」が無いことを明示する（"内部品質のみ" など）。曖昧にしない
